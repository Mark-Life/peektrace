# Peektrace Inspector (`apps/inspector`)

Vite + React 19 + Tailwind v4 UI for Peektrace — a loopback-only forensic
inspector for Claude Code, Codex, Pi and OpenCode sessions, stats, Claude
memory, and the capability matrix. State is wired with
[`@effect-atom/atom-react`](https://github.com/tim-smart/effect-atom) over the
`/api` JSON routes of the Rust `peektrace serve`.

## Layout

```
src/
  main.tsx                      mount + ThemeProvider + globals.css
  app.tsx                       shell + hash-routed sections
  components/
    app-shell.tsx               left nav (Sessions / Stats / Memory / Settings)
    section-header.tsx          shared page heading
  routes/                       one module per section
  lib/
    api.ts                      typed fetch client for `/api` (Effect)
    api-types.gen.ts            wire types, generated by crates/protocol
    atoms.ts                    per-route query atoms
    live.ts                     `/api/events` stream, `/api/watch` fallback
    watch-atoms.ts              refresh atoms when the server's versions move
    result-view.tsx             render the Result loading/success/failure union
    routes.ts                   tiny zero-dep hash router
    theme.tsx                   next-themes provider + toggle (dark-first)
    vite-env.d.ts               typed import.meta.env
```

## Data layer (Effect-Atom)

`lib/api.ts` wraps `fetch`. Each call, such as `apiGet<AllVaults>("/api/memory")`,
is an `Effect` that fails with the server's typed `ApiError` or a
`TransportError` (no answer, or a non-JSON answer such as a 401). The wire types
in `lib/api-types.gen.ts` come from the Rust structs: regenerate them with
`cargo test -p peektrace-protocol`, never by hand.

`lib/atoms.ts` turns each call into an `Atom<Result<Success, ApiFailure>>`.
`Result` is the loading/success/failure **discriminated union** — no `isLoading`
/ `error` flag bags. Render it with `<ResultView result={...}>{(value) => …}</ResultView>`.

Live refresh: `lib/live.ts` opens one `EventSource` on `/api/events`, which
pushes `{memory, sessions}` versions on connect and on every change. If the
stream cannot open, it polls `/api/watch` every second. `lib/watch-atoms.ts`
refreshes only the atoms whose version moved.

The **base URL is the single knob**. It defaults to `""` (same origin) so `/api`
resolves against whatever host is serving the page. Override at build time with
`VITE_PEEKTRACE_BASE_URL` to point the UI at a remote `peektrace serve`.

## Transport: dev vs prod

Both modes hit the **same** paths (`/api`, `/api/events`); only who answers
them differs. The backend is the Rust binary (`crates/cli`, bin `peektrace`).
The TypeScript `apps/cli` server speaks `/rpc` and does not answer `/api`.

### Dev — Vite dev server + proxy

1. Start the backend in one terminal, from the repo root:

   ```sh
   cargo run -p peektrace-cli -- serve --no-open --port 4321
   ```

2. Start the Vite dev server in another:

   ```sh
   cd apps/inspector && bun run dev
   ```

`vite.config.ts` proxies `/api` → `http://127.0.0.1:4321`. Override the target
with `PEEKTRACE_API_TARGET`. HMR + the live backend run side by side. When you
restart `serve`, open tabs fall back to polling and recover on their own.

### Prod — same-origin, served by `peektrace serve`

```sh
cd apps/inspector && bun run build                  # emits dist/
cd ../.. && cargo run --release -p peektrace-cli -- serve
```

A release build embeds `apps/inspector/dist`, so build the UI first. A debug
build without embedded assets serves the repo's `dist/` from disk.
`PEEKTRACE_CLIENT_DIR` points either build at another folder.

From the repo root, `bun run serve` does both in one step (build inspector → run
`peektrace serve`).

`peektrace serve` serves the static `dist/` at `/` (SPA fallback to
`index.html`) and the API at `/api` on the **same origin**, so the default
`BASE_URL=""` just works. No proxy, no CORS.

## Safety: pointing at a throwaway projects root

Memory/session resolution reads `~/.claude/projects` by default. Set
`PEEKTRACE_CLAUDE_PROJECTS` to redirect it at a temp dir (used by automated tests
so they never touch real memories):

```sh
PEEKTRACE_CLAUDE_PROJECTS=/tmp/seed-projects \
  cargo run -p peektrace-cli -- serve --no-open --port 4321
```
